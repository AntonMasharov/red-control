# Аудит проекта — 3 октября 2026 года

## Область проверки

Проверены структура приложения, связи модулей и ресурсов, зависимости, сборка каталога, локальное хранение и миграции, разделение записей по кампании и УИК, основные пользовательские сценарии, платформенные адаптеры, тесты и документация. Изменения выполнялись в существующем проекте без изменения идентификаторов каталога и формата резервных копий.

## Исправления

- Проверка номера телефона вынесена в `src/data/phone.ts`: интерфейс и хранилище используют одно правило. Добавлены положительные и отрицательные проверки, нормализация российских номеров и сохранение международных номеров.
- Изменение копии заметки проверяет принадлежность кампании и участку. Неизвестный ID и чужой участок не изменяют состояние или журнал. Событие изменения содержит новый текст.
- Соединение SQLite публикуется только после успешной инициализации таблицы. Повторная попытка после ошибки действительно повторяет инициализацию.
- Ошибка чтения начальной ссылки больше не оставляет необработанное отклонение Promise при запуске приложения.
- Открытие явки до выбора участка направляет к выбору контекста.
- Экспорт жалобы отсутствует по требованиям продукта; текст сохранённого документа доступен для копирования.
- Веб-экспорт удаляет временную ссылку и освобождает Blob URL даже при отказе браузера выполнить загрузку.
- Версия в интерфейсе берётся из `app.json`, вместо устаревшей надписи 0.1. Веб-интерфейс сообщает о необходимости сети для загрузки сайта.
- Обязательные зависимости тестов указаны явно. `test-renderer` закреплён на 1.2.0, совместимом с React 19.2; прежняя автоматически разрешённая версия 1.3.0 требовала другого React reconciler.
- Добавлены единая команда проверки, отчёт покрытия, пороги покрытия и GitHub Actions.

## Проверки и ограничения покрытия

Исходное состояние: 47 тестов Node и 11 тестов Jest проходили; покрытие строк Jest составляло 52,94% при включении всех TypeScript-модулей.

Итоговый запуск: 61 тест Node, 26 тестов Jest и 3 сценария Cypress прошли. Проверка типов и каталога, чистая установка зависимостей, веб-сборка и экспорт Android/iOS прошли. Покрытие Jest: строки — 75,38%, операторы — 73,47%, функции — 72,68%, ветви — 67,06%. Исходное и итоговое измерения имеют небольшое различие состава: удалены мёртвые модули и исключены сгенерированные регистрации; прирост нельзя приписывать только новым тестам.

Подробная карта сценариев и команды находятся в [руководстве по тестированию](testing.md). Добавлены проверки первого запуска, библиотеки, дерева комиссий, контроллера приложения, хранения, открытия документов, экспорта, ошибок и разделения данных. Браузерные сценарии проверяют реальную кампанию и сохранение записей после перезагрузки.

Полное покрытие каждого варианта поведения и всех ветвей ещё не достигнуто. В частности, системные разрешения, реальное воспроизведение видео, фоновые переходы и поведение установленных просмотрщиков требуют проверки на устройствах. Процент Jest не учитывает отдельный набор тестов Node; показатели нельзя объединять простым сложением.

## Зависимости и безопасность

`npm audit --omit=dev` сообщил о 16 пакетах с высокой серьёзностью; полный `npm audit`, включая инструменты разработки и тестов, — о 47. Оба отчёта содержат те же два первичных предупреждения, распространяющиеся по дереву зависимостей. Это не 47 независимых ошибок приложения:

- `braces` 3.0.3: исчерпание стека на глубоко вложенных шаблонах — [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
- `node-forge` 1.4.0: проверка подписи RSA PKCS#1 v1.5 — [GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv).

Проверка npm registry на дату аудита показала, что эти версии остаются последними опубликованными. Затронуты цепочки Expo CLI/Metro и React Native. Наличие пакета в разделе dependencies само по себе не доказывает эксплуатацию уязвимости в конечной мобильной сборке. Автоматический откат Expo до 44 или React Native до 0.72, предложенный npm, несовместим с текущей архитектурой и не применён. Повторяйте аудит перед выпуском и обновляйте транзитивные зависимости после публикации исправлений.

Локальные записи хранятся без отдельного шифрования приложения. Данные резервной копии содержат личные сведения; серверная авторизация и синхронизация отсутствуют. Это существующие свойства продукта, а не функции, добавленные аудитом.
