# Ветки решения проблем

Редактируемый источник: `src/content/global/problem-solving.yaml`.

`stages` содержит этапы с постоянными идентификаторами. Для каждого этапа задаются
заголовок (`title`), инструкция (`description`), подпись выполненного действия
(`completedLabel`) и тип (`kind`: `oral`, `complaint` или `action`). Тип `complaint`
добавляет кнопку подготовки жалобы. Правовые основания берутся из самого пункта.

`default` задаёт последовательность идентификаторов по умолчанию:

```yaml
default: [oral, complaint, police, prosecutor]
```

В `src/content/global/tasks.yaml` или файле задач кампании пункт может переопределить
порядок и количество этапов, а также указать конкретный пример жалобы:

```yaml
roadmap-home:item-03:
  id: roadmap-home:item-03
  # Остальные поля пункта сохраняются.
  problemSolving: [oral, complaint]
  complaintId: home-voting-departure-marks
```

Если `problemSolving` отсутствует, применяется `default`. Пустой список `[]`
скрывает ветку для пункта. `complaintId` — идентификатор из `checkbox_items`
в `complaints.yaml` кампании. Если он не задан, пользователь выбирает пример
из доступных жалоб. Сборка проверяет идентификаторы этапов и ссылки на жалобы.

После изменения контента выполните `npm run build:content`.

Открытие «Проблема?» показывает первое действие и не создаёт запись. Отметка
выполненного действия сохраняет историю и открывает вопрос «Проблема устранена?».
Ответ «Нет» открывает следующий этап; «Да, решена» закрывает проблему.
«Пока жду ответа» сохраняет ожидание. История и заметки раскрываются отдельно. Сохранение или экспорт черновика не отмечает жалобу поданной.

«Проблема решена» устанавливает галочку у пункта. Установка галочки непосредственно
в списке также закрывает активную проблему. История сохраняется и доступна по ссылке
«Решено · История». Снятие галочки вновь открывает сохранённую ветку.

Прогресс хранится локально отдельно для выборов, участка, даты, пункта и повторения
этапа (например, отдельного выезда). Он включается в экспорт наблюдений и восстанавливается
при повторном запуске приложения. Переименование идентификаторов этапов после начала
работы меняет их связь с сохранённой историей; для правки текста сохраняйте идентификаторы.
