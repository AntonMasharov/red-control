# Красный контроль

**Версия 1.0** · Приложение для наблюдателей от КПРФ

«Красный контроль» помогает подготовиться к наблюдению и работать на избирательном участке: изучать материалы, следовать дорожной карте, учитывать явку, фиксировать проблемы и готовить жалобы.

Приложение разработано на React Native для Android, iOS и веба. Материалы входят в сборку, записи наблюдателя сохраняются на устройстве. В конфигурации проекта версия 1.0 записана как `1.0.0`.

## Возможности

- **Подготовка.** Теория, документы, видео и правовые нормы с поиском и ссылками на источники.
- **Выбор кампании и участка.** Дерево комиссий, поиск УИК по номеру и адресу, сохранение ФИО наблюдателя и выбранного участка.
- **Дорожная карта.** Этапы работы по дням голосования, отметки выполнения, заметки и повторяемые этапы, включая надомное голосование.
- **Решение проблем.** Пошаговые действия, фиксация прогресса, ожидания ответа и результата, переход к подготовке жалобы.
- **Учёт явки.** Счётчик, отмена последнего добавления, исправления с указанием причины, сверки с комиссией, график и история.
- **Подготовка жалоб.** Выбор нарушения, заполнение шаблона, редактирование текста, сохранение черновика и отметка подачи.
- **Мой участок.** Сведения об УИК и редактирование локального состава комиссии.
- **Контакты.** Контакты штаба и личные контакты наблюдателя с переходом к звонку.
- **Экспорт записей.** Выгрузка локального состояния в JSON из окна выбора выборов.

## Быстрый запуск

Для разработки используйте Node.js 24 и npm. Зависимости зафиксированы в `package-lock.json`.

Текущее окружение разработки и сборки использует Expo; приложение также использует его модули для хранения данных, видео и работы с файлами. Зависимости устанавливаются командой `npm ci`. Каталоги `node_modules/` и `.expo/` исключены из Git, а описание зависимостей и конфигурация остаются в репозитории.

```sh
npm ci
npm run web
```

Откройте [localhost:8081](http://localhost:8081). Каталог материалов автоматически собирается перед запуском.

```sh
npm start          # сервер разработки Expo
npm run android   # сборка и запуск на Android
npm run ios       # сборка и запуск на iOS
```

Для Android требуется настроенное окружение Android SDK. Для iOS нужны macOS и Xcode.

## Сборка

### Веб

```sh
npm run build:web
npm run preview
```

Сборка сохраняется в `dist/`. Локальный просмотр доступен на [localhost:8082](http://localhost:8082).

### Android и iOS

```sh
npm run build:mobile
```

Команда экспортирует ресурсы обеих платформ в `dist-native/`, но не создаёт APK или IPA. Для установочных пакетов Android в `eas.json` предусмотрены два профиля:

```sh
npx eas-cli build --platform android --profile preview     # APK
npx eas-cli build --platform android --profile production  # AAB
```

Сборка через EAS требует доступа к настроенному проекту Expo и настройки подписи. Идентификатор приложения для Android и iOS — `ru.redcontrol.observer`.

## Материалы и кампании

Содержимое приложения хранится в YAML: кампании, комиссии, инструкции, маршруты, правовые нормы, шаблоны жалоб и контакты. При сборке исходники проходят проверку и превращаются в каталог приложения.

В репозитории включена кампания `deputy-2026` («Депутатские выборы 2026») со статусом `draft`. Даты и сведения в ней являются данными каталога; перед использованием в конкретной кампании их необходимо проверить вместе с материалами и контактами штаба.

### Что и где редактировать

В дереве ниже **РЕД.** означает редактируемые исходники, **ДОБ.** — место для добавления файлов, **АВТО** — результат сборки, который нельзя редактировать вручную. Папка `<id-кампании>/` обозначает любую кампанию, например `deputy-2026`.

```text
src/content/
├── catalog-manifest.yaml             РЕД. Список кампаний и ревизия каталога
├── catalog.generated.json            АВТО Собранный каталог приложения
├── source-assets.generated.ts        АВТО Регистрация встроенных файлов
├── lesson-videos.generated.ts        АВТО Регистрация видео для уроков
├── catalog.schema.json               Правила структуры каталога для разработчиков
│
├── global/                           Общие материалы для всех кампаний
│   ├── app-settings.yaml             РЕД. Уведомление, время сверок, роли контактов
│   ├── topics.yaml                   РЕД. Темы и учебные материалы
│   ├── tasks.yaml                    РЕД. Пункты чек-листа и их правовые ссылки
│   ├── blocks.yaml                   РЕД. Этапы и группы пунктов чек-листа
│   ├── roadmaps.yaml                 РЕД. Порядок этапов и дни их выполнения
│   ├── problem-solving.yaml          РЕД. Шаги решения проблем и их порядок
│   ├── complaints.yaml               РЕД. Жалобы, примеры нарушений, правовые ссылки
│   ├── complaint-templates.yaml       РЕД. Шапки и концовки шаблонов жалоб
│   ├── documents.yaml                РЕД. Карточки документов в библиотеке
│   ├── contacts.yaml                 РЕД. Общий справочник контактов
│   ├── headquarters.yaml             РЕД. Штабы и привязанные к ним контакты
│   ├── laws/
│   │   └── laws.yaml                 РЕД. Правовые нормы и ссылки на источники
│   ├── documents/
│   │   ├── sources.yaml              РЕД. Описания и имена оригиналов документов
│   │   └── *.docx, *.pdf, *.rtf, …    ДОБ. Оригиналы документов
│   └── videos/
│       ├── sources.yaml              РЕД. Описания и имена видео
│       └── *.mp4                     ДОБ. Локальные видео
│
└── elections/
    └── <id-кампании>/
        ├── manifest.yaml             РЕД. ОБЯЗАТЕЛЬНО: название, даты, выбор материалов
        ├── commissions.yaml          РЕД. ОБЯЗАТЕЛЬНО: дерево комиссий и участки
        └── content/                  ДОБ. НЕОБЯЗАТЕЛЬНО: материалы только этой кампании
            ├── topics/*.yaml         РЕД. Учебные материалы
            ├── tasks/*.yaml          РЕД. Пункты чек-листа
            ├── blocks/*.yaml         РЕД. Этапы и группы пунктов
            ├── roadmaps/*.yaml       РЕД. Порядок этапов и дни выполнения
            ├── laws/*.yaml           РЕД. Правовые нормы
            ├── sources/*.yaml        РЕД. Описания файлов и пути к оригиналам
            └── documents/*.yaml      РЕД. Карточки документов
```

Папки `content/` можно создать при необходимости; в текущей кампании материалы выбираются из `global/`. В перечисленных папках `content/<таблица>/` разрешены несколько YAML-файлов и вложенные папки. ID локальных записей должны начинаться с `<id-кампании>:` и быть уникальными: локальные материалы добавляются к общим, а не заменяют их.

Общие материалы влияют на все кампании, которые на них ссылаются. Жалобы, шаблоны, контакты, штабы и настройки решения проблем задаются в `global/`; отдельный `elections/<id>/complaints.yaml` в текущей структуре не используется.

Оригиналы документов и видео по умолчанию ищутся в `global/documents/` и `global/videos/`. Поле `file` в описании источника позволяет указать другой путь относительно `src/content/`. Одного добавления файла недостаточно — зарегистрируйте его в соответствующем `sources.yaml`.

Настройки из `global/app-settings.yaml` также собираются в `src/core/constants/app-settings.generated.json` — этот файл не редактируется вручную. В качестве примера используйте существующую кампанию в `src/content/elections/deputy-2026/`.

После изменения материалов выполните:

```sh
npm run build:content
npm run check:content
```

Файлы `*.generated.*` создаются автоматически. Изменяйте YAML-исходники; при обновлении кампании сохраняйте идентификаторы сущностей, к которым привязаны записи наблюдателей. Версия материалов и ревизия каталога учитываются отдельно от версии приложения.

## Проверки

```sh
npm run check             # единая проверка каталога, типов, тестов и покрытия
npm run check:content     # актуальность и корректность каталога
npm run typecheck         # проверка типов
npm test                  # тесты данных и логики
npm run test:integration  # сценарии интерфейса
npm run test:coverage     # покрытие Jest и HTML-отчёт в coverage/
```

В GitHub Actions эти проверки выполняются вместе со сборками и браузерными сценариями. Тесты Node используют исторический каталог для проверки миграций, а сборка и Cypress — реальные материалы. Пороги покрытия и проверки на устройствах описаны в [руководстве по тестированию](docs/testing.md).

Для браузерных тестов соберите веб-версию и запустите `npm run preview`, затем в другом терминале выполните `npm run test:e2e`. При первом запуске может потребоваться установка Cypress командой `npx cypress install`.

## Хранение данных и работа без сети

На Android и iOS записи хранятся в SQLite, в вебе — в `localStorage`. Данные разделены по кампании и участку и сохраняются после перезапуска и переключения между ними.

В установленном мобильном приложении встроенные материалы и сохранённые записи доступны без сети. Веб-версия требует загрузки сайта; автономное кеширование и установка PWA пока не настроены.

Текущие границы возможностей:

- Серверная синхронизация, авторизация и отправка записей в штаб не подключены. Счётчики разных наблюдателей ведутся независимо.
- Текст сохранённой жалобы доступен для копирования. Подписание, подача и создание заполненного DOCX или PDF выполняются вне приложения.
- JSON-экспорт не включает двоичные вложения. Импорт резервной копии через интерфейс пока отсутствует.
- Напоминания о сверках явки работают в открытом приложении.
- Очистка данных приложения или браузера удаляет локальные записи.

Перед распространением сборки проверьте её на реальных телефонах: работу без сети, открытие документов и видео, экспорт и сохранение записей после обновления.
